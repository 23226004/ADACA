# AI Engineering Standard (Draft)

## 개요

AI를 활용한 개발이 보편화되면서 누구나 빠르게 기능을 구현할 수 있게 되었습니다.

하지만 프로젝트마다 개발 방식, 문서, 구조가 달라지면 협업이 어려워지고 프로젝트 품질이 사람마다 달라지는 문제가 발생합니다.

따라서 AI를 활용하더라도 **동일한 기준으로 프로젝트를 관리하고 협업할 수 있는 운영 표준(Engineering Standard)** 을 구축하고자 합니다.

***

# 1. Documentation Standard (문서 표준)

## 개요

프로젝트에서 사용하는 모든 문서를 동일한 형식과 구조로 관리하는 규칙입니다.

문서는 프로젝트를 이해하기 위한 기준이며, AI와 개발자 모두가 동일한 정보를 기반으로 작업할 수 있도록 합니다.

### 목적

* 프로젝트 이해도 향상
* 인수인계 시간 단축
* 의사결정 이력 관리
* AI가 프로젝트를 정확하게 이해할 수 있는 기반 제공

### 기대 효과

* 프로젝트마다 동일한 문서 구조 유지
* 신규 참여자의 빠른 프로젝트 이해
* AI의 프로젝트 이해도 향상
* 변경 이력 추적 가능

### 관리 대상

* 프로젝트 개요
* 요구사항 명세서
* 아키텍처 설계서
* API 명세서
* 데이터베이스 설계서
* 아키텍처 의사결정 기록(ADR)
* 기능/변경 제안서
* 배포 노트
* 변경 이력

### 제어해야 하는 부분

* 필수 문서 정의
* 문서 템플릿
* 작성 책임자
* 최신화 기준

***

# 2. Project Structure (프로젝트 구조)

## 개요

모든 프로젝트를 동일한 디렉터리 구조와 계층으로 생성하는 표준입니다.

프로젝트 내부를 변경 가능 범위(Level)로 구분하여 유지보수성과 안정성을 확보합니다.

### 목적

* 프로젝트 간 일관성 확보
* 공통 모듈 재사용
* AI 수정 범위 명확화
* 유지보수 비용 감소

### 기대 효과

* 프로젝트 구조 표준화
* 기능 위치 탐색 용이
* AI의 안전한 수정 범위 확보
* 재사용성 향상

### 예시

```
Project
├── docs
├── src
│   ├── Core
│   ├── Platform
│   ├── Modules
│   └── Project
├── tests
└── release
```

### 제어해야 하는 부분

* 디렉터리 구조
* Level 정의
* 공통 코드 관리
* 수정 가능 범위

***

# 3. Development Workflow (개발 프로세스)

## 개요

기능 요청부터 배포까지 동일한 절차를 따르도록 정의하는 개발 프로세스입니다.

AI와 개발자는 동일한 Workflow를 기반으로 작업합니다.

### 목적

* 작업 절차 통일
* 개발 누락 방지
* 자동화 기반 마련

### 기대 효과

* 동일한 개발 방식 유지
* 진행 상황 추적
* AI 자동화 용이

### 예시 Workflow

```
요구사항
    ↓
Issue 생성
    ↓
개발
    ↓
테스트
    ↓
문서 업데이트
    ↓
Pull Request
    ↓
Merge
    ↓
Release
```

### 제어해야 하는 부분

* 작업 순서
* 완료 조건(Definition of Done)
* 리뷰 절차
* 테스트 기준

***

# 4. GitHub Workflow (GitHub 운영 규칙)

## 개요

GitHub를 단순 저장소가 아닌 협업 플랫폼으로 활용하기 위한 운영 규칙입니다.

### 목적

* 변경 이력 관리
* 협업 품질 향상
* 코드 리뷰 체계화

### 기대 효과

* 변경 이력 추적
* 리뷰 문화 정착
* 배포 안정성 향상

### 관리 대상

* Issue
* Branch
* Commit
* Pull Request
* Release

### 제어해야 하는 부분

* Branch 전략
* Commit Convention
* PR Template
* Merge 정책

***

# 5. Project Context (프로젝트 컨텍스트)

## 개요

프로젝트를 이해하기 위해 필요한 핵심 정보를 하나의 컨텍스트로 관리합니다.

AI와 개발자는 동일한 Project Context를 기반으로 프로젝트를 이해하고 작업합니다.

### 목적

* 프로젝트 이해 비용 감소
* AI Context 제공
* 프로젝트 현황 공유

### 기대 효과

* 프롬프트 작성 최소화
* AI의 프로젝트 이해도 향상
* 신규 참여자의 빠른 온보딩

### 관리 대상

* 프로젝트 목적
* 현재 상태
* 기술 스택
* 아키텍처
* 공통 규칙
* 용어집

### 제어해야 하는 부분

* 최신 상태 유지
* 프로젝트 요약
* 용어 통일
* 현재 작업 현황

# 핵심 목표

> AI와 사람이 동일한 기준으로 프로젝트를 이해하고 협업할 수 있는 운영
> 표준을 구축한다.

이 표준은 특정 AI 모델에 종속되지 않으며, 프로젝트 자체를 조직의 자산으로 만드는 것을 목표로 한다.
