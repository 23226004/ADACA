# 요구사항 명세서 — autodocs

> 엔진이 **무엇을** 해야 하는지. 어떻게는 `docs/architecture/architecture.md`.

## REQ-001 준수 상태 판정

### 목적

AI 도구가 작업 시작 시 "신규인지 기존인지, 표준을 따르고 있는지"를 재현 가능하게 알 수 있어야 한다.

### 요구사항

1. 프로젝트 루트를 입력받아 `new / legacy / partial / compliant` 중 하나를 반환해야 한다.
2. 판정은 manifest 와 파일 시스템만으로 결정되어야 하며, 실행 환경·모델에 따라 달라지지 않아야 한다.
3. 위반 항목은 check id, 심각도, 경로, 수정 힌트를 포함해야 한다.
4. 파일 시스템은 한 번만 스캔해야 한다.

### 수용 기준

- 빈 디렉터리 → new, 마커 없이 소스 있음 → legacy, init 직후 → compliant.

## REQ-002 신규 프로젝트 생성

### 요구사항

1. 표준 디렉터리, 계층 디렉터리, 필수 문서, 조건부 문서(프로필 기준), AI 포인터 파일, 마커를 생성해야 한다.
2. 이미 존재하는 파일·디렉터리는 절대 변경하지 않아야 한다.
3. 문서 내용은 `standard/templates/` 에서 오며, 프로젝트 이름·언어·날짜 등을 치환해야 한다.

### 수용 기준

- 빈 디렉터리에서 `init` 직후 `check` 가 error 0 으로 통과한다.

## REQ-003 기존 프로젝트 도입 (adopt)

### 요구사항

1. `init` 과 동일하게 결정론적으로 만들 수 있는 것을 생성해야 한다.
2. 계층에 속하지 않은 소스 파일 목록을 Proposal 형식 계획서로 출력해야 한다.
3. 소스 파일을 이동하거나 수정하지 않아야 한다 (판단은 사람/AI).

## REQ-004 의존성 방향 검사

### 요구사항

1. Python, TypeScript/Svelte, C# 소스의 import 를 계층으로 해석해 상향 의존을 검출해야 한다.
2. 상대 경로 import 와 `$lib` alias 를 해석해야 한다.
3. 계층 밖의 파일과 외부 패키지 import 는 무시해야 한다.

## REQ-005 표준을 코드에 하드코딩하지 않음

### 요구사항

1. 문서 종류, 필수 여부, 갱신 트리거, 계층 이름, 검사 목록, 심각도는 manifest 에서 읽어야 한다.
2. manifest 에 선언된 check 가 구현되지 않았으면 테스트가 실패해야 한다.
3. manifest 가 가리키는 템플릿이 없으면 테스트가 실패해야 한다.

## REQ-006 CLI 계약

### 요구사항

1. `audit`, `check`, `init`, `adopt` 네 명령을 제공해야 한다.
2. `check` 는 error 가 있으면 exit 1, 엔진 오류는 exit 2, 그 외 0 이어야 한다.
3. `--json` 으로 기계 판독 출력을 제공해야 한다 (어댑터용).
